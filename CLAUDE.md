# Lidd School CRM

CRM для репетиторской школы Lidd School (математика и информатика, ОГЭ/ЕГЭ и школьная программа).
Пользователи: владелец, администратор, педагоги. Интерфейс полностью на русском.

Источник требований: `docs/TZ-source.md` (исходное ТЗ на макеты) + этот файл.
**Если ТЗ и этот файл противоречат друг другу — прав этот файл.** В частности, пакеты на 4/8/12 занятий из ТЗ
отменены: в школе только абонемент на месяц и поурочная оплата (см. «Оплата»).

План работ по этапам: `docs/ROADMAP.md`. Схема БД: `prisma/schema.prisma`.

## Стек

- Next.js (App Router) + TypeScript (strict)
- Tailwind CSS + shadcn/ui, иконки lucide-react
- PostgreSQL + Prisma
- Аутентификация: Auth.js (credentials, email + пароль), роли в сессии
- Валидация: zod. Даты: date-fns (+ date-fns-tz)
- Тесты: Vitest (доменная логика), Playwright (ключевые сценарии, позже)
- Хостинг: российский облачный провайдер (Yandex Cloud / Selectel / Timeweb) — персональные данные
  граждан РФ по 152-ФЗ должны храниться в России. Не использовать Vercel/Supabase для продакшена.

## Принципы кода

- **Вся денежная и календарная логика — в `src/domain/`**: чистые функции без обращения к БД и UI,
  каждая покрыта unit-тестами. Компоненты и route handlers только вызывают домен.
- Деньги — целые рубли (`Int`). Часы — `Decimal(5,2)` в БД, `number` в домене (кратны 0,25).
- Все изменения денег (платежи, корректировки, выплаты, расходы) пишутся в `LedgerEntry` / `AuditLog`
  с автором и временем. Ничего финансового не удаляем — только сторно.
- Серверные действия проверяют роль на сервере, а не только скрывают кнопки в UI.
- Часовой пояс школы: `Asia/Vladivostok`. Все даты хранить в UTC, отображать в поясе школы.
- Формат: даты `ДД.ММ.ГГГГ`, время `ЧЧ:ММ`, неделя с понедельника, суммы `1 500 ₽` (неразрывный пробел).

## Роли

| Роль | Видит / может |
|---|---|
| Владелец (OWNER) | всё, включая ставки педагогов, зарплаты, прибыль, отчёты, настройки тарифов |
| Администратор (ADMIN) | уроки, задачи, клиенты, группы, педагоги (без ставок), абонементы, лиды, приём платежей и долги. **Не видит** ставки, зарплаты, расходы, прибыль, отчёты |
| Педагог (TEACHER) | только своё расписание, своих учеников и группы, свои задачи и «Мой заработок». Отмечает уроки и посещаемость |

## Оплата (главные правила бизнеса)

Цена считается **за урок-час** (60 мин). Урок 90 мин = 1,5 урок-часа, 45 мин = 0,75.

| Программа | Абонемент на месяц | Поурочно |
|---|---|---|
| ОГЭ / ЕГЭ (`EXAM`) | 1 500 ₽ | 1 700 ₽ |
| Школьная программа (`SCHOOL`) | 1 300 ₽ | 1 500 ₽ |

Групповые занятия — отдельный тариф (`Tariff.kind = GROUP`), **800–1 000 ₽ за урок-час** (точные значения
задаются в таблице тарифов).

Тарифы хранятся в таблице `Tariff` с датой начала действия (цены могут меняться — старые счета не пересчитываются).

### Абонемент на месяц (`MONTHLY`)
- Количество уроков считается **по расписанию ученика на календарный месяц** (серии `ScheduleSeries`).
- **25 числа** система формирует счёт (`MonthlyInvoice`) на следующий месяц:
  `сумма = Σ(часы урока × тариф абонемента)`.
- В счёте же считается, сколько вышло бы поурочно (`Σ часы × поурочный тариф`) и выгода.
- К счёту добавляется текущий долг ученика, если есть. Переплата (положительный баланс) вычитается из счёта,
  итог не меньше 0.
- Имя ученика в сообщении склоняется автоматически (`Client.gender`), при ошибке — ручное значение `Client.fullNameGen`.
- Родителю уходит сообщение (Telegram, позже WhatsApp/SMS) по шаблону:
  > Здравствуйте, {имя родителя}! В {месяце} у {ученика} {N} занятий по {предмету}: {даты, дни недели и время}.
  > Абонемент на {месяц}: {N} × {тариф} = {сумма}.
  > При поурочной оплате вышло бы {N} × {поурочный тариф} = {сумма}, абонемент выгоднее на {разница}.
  > {если долг: Также есть задолженность {долг}.} Итого к оплате: {итог} до 01.{мм}.
  > Оплатить: {ссылка}. Lidd School
- Срок оплаты — **1 число** месяца. Не оплачено к **3 числу** → автозадача администратору + напоминание.
- Ученик добавлен в середине месяца → счёт только на оставшиеся уроки месяца.
- Расписание изменилось после формирования счёта → пересчёт (настройка, по умолчанию включено), разница
  переносится в счёт следующего месяца.
- Настраиваемые правила переноса (по умолчанию):
  - урок отменён школой → стоимость переносится на следующий месяц;
  - уважительный пропуск (предупредили ≥ 24 ч) → переносится;
  - неуважительный пропуск → урок считается проведённым, деньги не переносятся.

### Поурочная оплата (`PER_LESSON`)
- Ссылка на оплату уходит родителю **за 48 ч** до урока, оплатить нужно **за 24 ч**.
- Не оплачено к дедлайну → урок помечается «под угрозой», создаётся автозадача администратору
  (решение: перевести в долг или отменить).
- Урок проведён без оплаты → запись долга в `LedgerEntry`.
- Неуважительный пропуск → урок списывается полностью, как проведённый.

### Баланс клиента
`баланс = Σ LedgerEntry.amount` (платежи «+», начисления за уроки и счета «−»). Отрицательный → красный +
автозадача «Напомнить об оплате».

## Зарплата педагогов

- Шаблон школы (`RatePlan`, `isDefault = true`): **700 ₽ за урок-час**.
- Надбавка за объём проведённых урок-часов **за календарный месяц** (`RateTier`):
  - от **30 ч** → **+10%**, от **45 ч** → **+15%** (берётся максимальная достигнутая ступень).
  - Режим применения (`bonusApply`): `WHOLE_MONTH` (по умолчанию) — процент ко всей сумме за месяц;
    `ABOVE_THRESHOLD` — только к часам сверх порога, прогрессивно (часы 30–45 → +10%, сверх 45 → +15%).
  - Надбавка применяется **только к почасовой части** (часы × ставка): доплата за учеников группы и пробные
    уроки идут без надбавки. Порог включительный (ровно 30 ч — уже +10%).
- Групповые занятия: ставка за урок-час + **100 ₽ за каждого присутствующего** ученика.
- Пробные уроки: фиксированно **500 ₽**, в объём часов для надбавки не входят.
- Неуважительный пропуск ученика: педагогу не начисляется (настройка `payForUnexcused`), и эти часы
  **не идут** в объём для надбавки.
- Отменённые уроки не начисляются и в часы не входят.
- Ставка **не зависит** от того, как платит ученик (абонемент или поурочно).
- Педагогу можно назначить индивидуальный план; история смен ставки хранится (`TeacherRatePlan.validFrom`).
  Ставка меняется **только с 1 числа месяца** — в одном месяце у педагога одна ставка.
- Выплата за месяц — 5 числа следующего месяца; авансы и выплаты фиксируются в `PayrollPayment`.

## Контрольные примеры (обязаны проходить в тестах `src/domain`)

Ноябрь 2026 начинается в воскресенье.

| Случай | Ожидание |
|---|---|
| ЕГЭ, абонемент, уроки по вс 60 мин, ноябрь 2026 | 5 уроков × 1 500 = **7 500 ₽**; поурочно 8 500 ₽; выгода 1 000 ₽ |
| ОГЭ, абонемент, вт + пт 60 мин, ноябрь 2026 | 8 уроков → **12 000 ₽** |
| Школьная, абонемент, пн + ср 60 мин, ноябрь 2026 | 9 уроков × 1 300 = **11 700 ₽**; поурочно 13 500 ₽ |
| То же + долг 1 700 ₽ | итого к оплате **13 400 ₽** |
| ЕГЭ поурочно, урок 90 мин | 1,5 × 1 700 = **2 550 ₽** |
| Педагог, 36 ч за месяц, WHOLE_MONTH | 36 × 700 = 25 200 → +10% = **27 720 ₽** |
| Педагог, 36 ч, ABOVE_THRESHOLD | 25 200 + 6 ч × 700 × 10% = **25 620 ₽** |
| Педагог, 48 ч | 33 600 → +15% = **38 640 ₽** |
| Педагог, 22 ч | **15 400 ₽**, надбавки нет |
| Групповой урок 90 мин, 5 присутствуют | 1,5 × 700 + 5 × 100 = **1 550 ₽** педагогу |

## Команды

Первый запуск (нужны Node 24+ и Docker):

```bash
cp .env.example .env          # затем задать AUTH_SECRET и SEED_PASSWORD
npm install
docker compose up -d          # PostgreSQL 16 на localhost:5432
npm run db:migrate            # применить миграции
npm run db:seed               # очистить базу и залить сид-данные
npm run dev                   # http://localhost:3000
```

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер Next.js |
| `npm run build` / `npm start` | продакшен-сборка и запуск |
| `npm test` | unit-тесты (Vitest), в т.ч. контрольные примеры |
| `npm run test:watch` | тесты в режиме наблюдения |
| `npm run typecheck` | проверка типов (`tsc --noEmit`) |
| `npm run lint` | ESLint |
| `npm run db:migrate` | `prisma migrate dev` — создать/применить миграцию после правки схемы |
| `npm run db:seed` | пересоздать сид-данные (**стирает базу**) |
| `npm run db:reset` | сбросить базу, применить миграции и сид |
| `npm run db:studio` | Prisma Studio для просмотра данных |

Пользователи сида: `owner@lidd.school`, `admin@lidd.school`, `kim@lidd.school`, пароль — `SEED_PASSWORD` из `.env`.

## Устройство кода

- `src/domain/` — чистая доменная логика и тесты (`*.test.ts` рядом с модулем). Календарные даты — строки
  `LocalDate` («2026-11-01»), моменты времени — `Date` в UTC; поля `@db.Date` переводить через
  `fromDbDate` / `toDbDate` (`src/domain/calendar.ts`).
- `src/lib/access.ts` — матрица прав (`PERMISSIONS`), меню, вкладки финансов. Единственный источник правды о ролях.
- Защита в два уровня: `src/proxy.ts` (вход и раздел по роли, `authorized` в `src/server/auth.config.ts`) и
  `requirePermission()` из `src/server/session.ts` в каждой странице и серверном действии.
  Данные педагога фильтровать по `user.teacherId` в запросе, а не в интерфейсе.
- Next.js 16: `middleware` переименован в `proxy`; Cache Components выключены (`next.config.ts`).
  Перед использованием незнакомого API Next смотреть `node_modules/next/dist/docs/`.
- Prisma 6 (`prisma-client-js`). Склонение имён — `petrovich` с исправлениями в `src/domain/names.ts`.
