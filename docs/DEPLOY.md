# Запуск CRM на сервере

Всё работает на одном сервере в Docker: сайт, фоновый процесс (счета, напоминания, Telegram), база PostgreSQL,
HTTPS (Caddy, сертификат выпускается сам) и ночные резервные копии. Данные хранятся в России (152-ФЗ).

## 1. Что понадобится

| Что | Где | Примерная цена |
|---|---|---|
| Сервер (VPS): Ubuntu 24.04, 2 ядра, 4 ГБ памяти, 40–50 ГБ диска, регион — Россия | Timeweb Cloud / Selectel / Yandex Cloud | 1 000–1 500 ₽/мес |
| Домен или поддомен, например `crm.liddschool.ru` | у регистратора вашего домена | — |
| S3-хранилище для копий базы (рекомендуется) | там же, где сервер («Объектное хранилище») | 50–100 ₽/мес |
| Telegram-бот (`@BotFather`) | Telegram | бесплатно |

## 2. Домен

В настройках DNS домена добавьте **A-запись**: `crm` → IP-адрес сервера. Обновление занимает от нескольких минут до часа.

## 3. Подготовка сервера (один раз)

Подключитесь к серверу по SSH (`ssh root@IP`) и выполните:

```bash
curl -fsSL https://get.docker.com | sh
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable
git clone https://github.com/titovamailru1-sudo/liddschool.git /opt/lidd-crm
cd /opt/lidd-crm
cp .env.production.example .env
nano .env
```

Репозиторий приватный — для `git clone` понадобится токен GitHub (Settings → Developer settings → Fine-grained token,
доступ только на чтение этого репозитория) или deploy key.

## 4. Настройки (`.env`)

| Переменная | Что указать |
|---|---|
| `DOMAIN`, `APP_URL` | ваш домен: `crm.liddschool.ru` и `https://crm.liddschool.ru` |
| `DB_PASSWORD` | случайный пароль: `openssl rand -hex 24` |
| `AUTH_SECRET` | случайный ключ: `openssl rand -base64 32` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | токен и имя бота от `@BotFather` |
| `ALERT_TELEGRAM_CHAT_ID` | ваш id в Telegram — сюда придут сообщения об ошибках и неудачных копиях. Узнать: написать `@userinfobot`, затем один раз написать своему боту `/start` |
| `BACKUP_S3_*` | ключи и имя бакета хранилища (пусто — копии только на сервере) |

## 5. Запуск

```bash
docker compose -f compose.prod.yml up -d --build
docker compose -f compose.prod.yml run --rm app npm run init:school -- owner@почта.ru "Имя Фамилия"
```

Вторая команда создаёт тарифы школы, шаблон ставки педагогов и учётную запись владельца и печатает **ссылку**:
откройте её и задайте пароль. Повторный запуск безопасен (ничего не дублирует, выдаёт новую ссылку).

Дальше в CRM: «Педагоги» → добавить педагогов и выдать им ссылки-приглашения; «Абонементы → Тарифы» — проверить цены
(групповые заданы как 800 / 1 000 ₽); меню профиля → «Настройки» — реквизиты для QR-оплаты.

> **Не запускайте** на сервере `npm run db:seed` и `db:reset` — они стирают базу.

## 6. Проверка

- `https://ваш-домен/api/health` → `{"ok":true,"db":true,"worker":true,...}`.
  `worker:false` — фоновый процесс не работал последние 5 минут.
- Подключите бесплатный мониторинг доступности (любой сервис проверки сайтов) на адрес `/api/health`:
  он пришлёт уведомление, если сервер или воркер упадёт. Адрес не содержит персональных данных.
- Проверка копий сразу после запуска:
  ```bash
  docker compose -f compose.prod.yml exec backup /scripts/backup.sh
  ls -lh backups/
  ```
  Если указан S3 — в бакете должна появиться папка `lidd-crm/` с файлом.

## 7. Обновление до новой версии

```bash
cd /opt/lidd-crm && sh deploy/deploy.sh
```

Скрипт забирает код из GitHub, собирает образ, применяет миграции базы и перезапускает сайт и воркер (перерыв — около
минуты), затем проверяет `/api/health`.

## 8. Резервные копии и восстановление

- Каждую ночь в `BACKUP_TIME` (по умолчанию 03:00 по Владивостоку) — копия в папке `backups/` на сервере
  (хранится `BACKUP_KEEP_DAYS` дней) и в S3 (`BACKUP_S3_KEEP_DAYS` дней). Неудача → сообщение в Telegram.
- Восстановить базу из копии (сайт на время остановится, текущие данные заменятся):
  ```bash
  sh deploy/restore.sh backups/lidd-2026-10-12_0300.dump
  ```
  Копию из S3 сначала скачайте в `backups/` (через веб-интерфейс хранилища или `rclone`).
- Раз в несколько месяцев стоит проверять восстановление на отдельном сервере.

## 9. Полезные команды

```bash
docker compose -f compose.prod.yml ps                     # что запущено
docker compose -f compose.prod.yml logs -f --tail=100 app worker   # логи сайта и воркера
docker compose -f compose.prod.yml restart worker         # перезапустить воркер
docker compose -f compose.prod.yml exec db psql -U lidd lidd_crm   # консоль базы (осторожно)
```

## 10. Ошибки и безопасность

- Ошибки сайта и воркера пишутся в лог и приходят в Telegram (`ALERT_TELEGRAM_CHAT_ID`) — одинаковые не чаще
  раза в 10 минут, без персональных данных.
- Вход: после 5 неверных паролей подряд вход по этому email блокируется на 15 минут.
- База не открыта в интернет; наружу открыты только 80/443 (Caddy) и SSH.
- Персональные данные: как оператор ПДн школа подаёт уведомление в Роскомнадзор и публикует политику обработки
  персональных данных — это делает владелец, не CRM.
